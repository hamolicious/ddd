# `web/` build contracts (M2)

Five builder areas fill in this scaffold in parallel. The tree already
typechecks: every interface exists, every signature is final, and the bodies that
are not implemented throw `Error("not implemented: …")`.

**Scope: SPEC §9 M2 only.** The offline substrate — projection store, sync client,
local query engine, Wasm core — plus a plain-TypeScript demo page and the two
harnesses. **No React, no plugin loader, no import maps, no extension registry:
that is M3, and nothing here may import `react`.**

[`../backend/PROTOCOL.md`](../backend/PROTOCOL.md) is authoritative for everything
on the wire. `kernel/src/protocol.ts` mirrors it and nothing else.

**The three rules**

1. **Never edit a file owned by another area.** If you need a change there, say so
   in your report — do not make it.
2. **Never change a frozen signature** (every `export interface` and every public
   method listed below). Adding an *optional* field to an options object is the one
   exception, and it still gets announced.
3. **Never edit `package.json`, `tsconfig.json`, `vite.config.ts` or
   `protocol.ts`, and never add a dependency.** Everything M2 needs is declared.
   `protocol.ts` moves only when `PROTOCOL.md` moves.

Supporting rules:

- `npm run typecheck && npm run test` must stay green — that is the gate.
- Nothing in `kernel/` may touch the DOM. The demo page is where the DOM lives.
- The kernel never reimplements parsing, title resolution or filter evaluation in
  TypeScript. It calls the Wasm core (SPEC §2: parity by construction).
- No timestamp arithmetic for ordering, ever: order is `seq` and the CRDT
  (PROTOCOL.md §5).

## Area: web-store

**Owns:** `kernel/src/store/**`.

**Must not touch:** `protocol.ts`, `sync/**`, `query/**`.

Hard requirements (SPEC §4.1; PROTOCOL.md §2.4):

- **`applyRows` is one `readwrite` transaction** spanning `projection` + `meta`.
  The checkpoint may never be ahead of the rows it describes — a crash between the
  two is exactly how a client silently loses a document forever.
- Rows are **LWW by `seq`**: a row whose `seq` is not newer than the stored one is
  ignored (and reported in `AppliedRows.ignored`). `purged` rows delete.
- `iterate` uses a **cursor**, never `getAll`: 5 000 rows of up to 1 MiB is the M2
  gate (SPEC §9 M2), not a `Vec` to build in memory.
- `retainOnly` is the only garbage-collection path, and only after a *complete*
  bootstrap pass.
- `clear()` happens on explicit logout and nothing else — never on a 401, never on
  `feed.reset` (SPEC §5.3).
- `subscribe` fires after the transaction commits, once per applied batch.

**Frozen interface** (`projection-store.ts`):

```ts
interface SyncCheckpoint { safeSeq: number; updatedAt: number;
                           coreSemanticsVersion: number | null; bootstrapped: boolean }
const EMPTY_CHECKPOINT: SyncCheckpoint;
interface AppliedRows { applied: string[]; purged: string[]; ignored: string[] }
interface StoreChange { applied: string[]; purged: string[]; safeSeq: number }
interface StoredRow extends ProjectionRow { seq: number }

interface ProjectionStore {
  open(): Promise<void>;                     close(): Promise<void>;
  get(id): Promise<StoredRow | undefined>;   getMany(ids): Promise<StoredRow[]>;
  iterate(options?: { includeDeleted?: boolean }): AsyncIterable<StoredRow>;
  count(options?: { includeDeleted?: boolean }): Promise<number>;
  applyRows(rows: FeedRow[], checkpoint: SyncCheckpoint): Promise<AppliedRows>;
  retainOnly(ids: ReadonlySet<string>): Promise<string[]>;
  checkpoint(): Promise<SyncCheckpoint>;     setCheckpoint(cp): Promise<void>;
  subscribe(listener: StoreListener): () => void;
  clear(): Promise<void>;
}
```

Plus, in `idb-store.ts` (schema is frozen; the class may grow private members):
`DB_NAME`, `DB_VERSION`, `STORE_PROJECTION`, `STORE_META`, `STORE_DOCS`,
`CHECKPOINT_KEY`, `StoredDocState`, `LifeManagerDb`, `IdbProjectionStore`.
`STORE_DOCS` is where hydrated replicas persist — implement `DocPersistence`
against it and hand it to the hydrator.

A `StoredDocState` additionally carries **`unsynced?: boolean`** (added by the M2
hardening pass), and two rules hang off it:

- `save(id, state, meta?)` records `meta.unsynced` alongside the bytes, so the flag
  and the blob can never disagree.
- **`prune` must never evict a replica flagged `unsynced`**, however old it is. Pure
  LRU here contradicts the hydrator's stated invariant and loses the only copy of an
  offline edit: edit one document offline, browse fifty more, reload — gone, with the
  projection row still there so nothing tells the user. The budget is a budget over
  *evictable* replicas.
- `peek(id)` reads a replica **without** touching its recency, and reports the flag.
  It is how the purge path answers "did this hold unsynced edits?" for a document
  that is on disk with nothing open. Optional on the interface; without it the
  hydrator has to assume "unsynced" and offer recovery.

## Area: web-sync

**Owns:** `kernel/src/sync/**` and `kernel/src/protocol.test.ts`.

**Must not touch:** `store/**` (program against `ProjectionStore`), `query/**`,
`protocol.ts`.

Hard requirements (PROTOCOL.md §§1–8):

- The persisted watermark is the server's `safe_seq`. Never `max(seq)` seen.
- `feed.reset` ⇒ run bootstrap **without clearing the store first**, then
  re-subscribe at the pinned `safe_seq`.
- `feed.resync` ⇒ re-subscribe at `from_seq`, keeping every local row.
- `doc.resync` ⇒ send a fresh `SYNC_STEP1` per affected document; `id` absent means
  all of them.
- `doc.error { code: "too_large", hint: "rest" }` ⇒ hydrate over
  `GET /api/documents/:id?format=crdt`, then re-subscribe with the resulting `sv`.
  **Check the hint**: the same code with no hint is a *write* the server refused for
  size (PROTOCOL.md §3.5), where the server state is unchanged and re-fetching the
  document is a pointless megabyte. Surface that one instead.
- A `purged` row ⇒ offer "restore your version as a new document" for **any** local
  replica holding unsynced edits, including one that is only in IndexedDB with
  nothing open (SPEC §4.1). That is the common shape, not the rare one: offline edits
  live in the `docs` blob and survive a reload, which is exactly when no `DocEntry`
  exists.
- Close **4401** ⇒ status `auth-required`, local data untouched. **4409** ⇒ stop and
  surface "reload". Backoff is `backoff.ts`; do not hand-roll another one.
- Awareness payloads pass through untouched, both directions.
- The LRU is ~20 hydrated docs; releasing the last handle unsubscribes.

`transport.ts` and `backoff.ts` are **already implemented** — extend them, don't
rewrite them. Frozen surface: `SyncTransport`, `TransportOptions`,
`TransportHandlers`, `resolveSyncUrl`, `subprotocols`, `backoffDelay`,
`backoffForClose`, `BackoffState`, `BootstrapClient`, `ndjson`, `FeedClient`,
`FeedState`, `SyncStatus`, `DocHydrator`, `HydratedDoc`, `DocPersistence`,
`SyncClient`.

## Area: web-query

**Owns:** `kernel/src/query/**`.

**Must not touch:** `store/**`, `sync/**`, `wasm/**`.

Hard requirements (SPEC §4.2):

- Filters are evaluated by the **Wasm core**. `WasmFilterEvaluator.matches` is the
  only path; a TypeScript reimplementation of the DSL is a contract violation.
- `compareRows` must match `core::filter::evaluator::compare_rows` exactly:
  missing sorts last, then type order (null < bool < number < string < list < map),
  then value, then `id` as the final tiebreaker. Test it against the Rust corpus
  (`backend/crates/core/corpus/filters.json`).
- The search index is **persisted and incrementally updated** — never a cold-start
  main-thread rebuild. `SEARCH_INDEX_VERSION` mismatch is the only full rebuild.
- Live queries re-run only when a change touches their result.

Frozen surface: `Query`, `QueryResult`, `SortKey`, `parseSortKey`, `resolvePath`,
`compareRows`, `FilterEvaluator`, `WasmFilterEvaluator`, `SearchIndex`,
`SearchHit`, `SearchOptions`, `SearchStats`, `SEARCH_FIELDS`,
`SEARCH_INDEX_VERSION`, `MiniSearchIndex`, `QueryEngine`, `Subscription`.

## Area: wasm

**Owns:** `kernel/src/wasm/**`, `scripts/wasm-smoke.mjs`, and
`backend/crates/core/src/wasm.rs`.

- `core-wasm.d.ts` and the Rust exports are **one contract**; they change together
  or not at all.
- `loadCore()` is idempotent and concurrency-safe; the browser passes no init
  argument, Node passes the `.wasm` bytes.
- A `core_semantics_version` mismatch against `welcome` means the client stops
  trusting its own parse and surfaces "reload" — it does **not** mean stop syncing.

Frozen surface: `CoreBindings`, `ParsedDocument`, `FilterJson`, `FilterRow`,
`filterRow`, `loadCore`, `resetCoreForTests`.

**Open:** `CoreBindings` exposes no date canonicalization, though the ABI exports
`normalize_date`. `parse_document` does not canonicalize dates but server
materialization does, so any kernel code re-deriving a projection row offline
disagrees with the server on real datetimes. `harness/src/core.ts` reaches into the
generated module as a stopgap; adding `normalizeDate()` to `CoreBindings` fixes it
for web-store and web-query too.

## Area: web-demo

**Owns:** `demo/**`.

It is wiring only: every behaviour it needs is a kernel call, and a missing
implementation must surface as a visible message rather than a blank page. It is
also the surface the Playwright smoke drives (SPEC §8): register → create → edit →
reload → offline edit → reconnect → converge. Keep the element ids (`#login`,
`#docs`, `#text`, `#status`, `#seq`, `#count`) — the smoke selects on them.

The textarea binding sends **minimal splices**, never whole-text replacement
(SPEC §3.2, §3.3). CodeMirror arrives in M3; do not add it here.

**Sign-out is the one destructive path** (SPEC §5.3): it clears the projection, the
checkpoint, the `docs` replicas and the search index. It must therefore consult
`client.pending` *first* and warn — logout with unsynced changes blocks until the
edits sync or the user explicitly discards them. Clearing the stores is what deletes
the only copy, so there is nothing to recover afterwards.

## Area: web-harness

**Owns:** `harness/**`.

- Drives the **real** kernel over a **real** socket against a running server. A
  faked transport proves nothing about convergence.
- Deterministic: same `--seed`, same run. A failure must be replayable.
- Exit non-zero unless `divergent` **and** `materializationMismatches` are both
  empty (SPEC §9 M2: convergence *and* materialization equality).
- `perf.ts` seeds 5 000 documents and reports bootstrap wall clock, feed catch-up
  latency, update round trips with 3 concurrent editors, and `/metrics` counters —
  the numbers the Android webview measurement is compared against.

Frozen surface: `HarnessConfig`, `DEFAULT_CONFIG`, `SimulatedClient`,
`ConvergenceReport`, `PerfReport`, `rng`, `parseArgs`, `spawnClients`,
`assertConvergence`, `seedWorkspace`.

## Dependencies

Already declared; do not add or bump.

Runtime: `yjs` (CRDT; `y-protocols` ships inside it), `minisearch` (local search),
`idb` (IndexedDB promises).
Dev: `typescript`, `vite`, `vite-node`, `vitest`, `@playwright/test`,
`@types/node`, `fake-indexeddb`.

`fake-indexeddb` was added against the no-dependency rule and is **ratified**: the
projection store is the offline half of SPEC §4.1 and cannot be unit-tested without
an IndexedDB, `vite.config.ts` is frozen and declares no `setupFiles`, so the
suites do `import "fake-indexeddb/auto"` themselves. Dev-only; nothing ships.
Likewise `tokio-tungstenite` under `[dev-dependencies]` on the server: the sync
layer cannot be integration-tested without a WebSocket *client*, and that crate was
already in `Cargo.lock` via axum's `ws` feature, so no new package is downloaded.

`y-codemirror.next` and CodeMirror are **M3**. React is **M3**.

## Commands

```
npm run typecheck        # tsc --noEmit (the gate)
npm run test             # vitest
npm run dev              # vite dev server; /api + /api/sync proxied to :8080
mise run wasm            # build the Wasm core into kernel/src/wasm/pkg
npm run e2e              # playwright: the SPEC §8 smoke + two-browser live collab
npm run harness:convergence -- --clients=6 --documents=25 --seed=7
npm run harness:perf
```

The harnesses and the Playwright config all read **`LM_SERVER`**, and Vite's `/api`
proxy reads it too — so a server on a non-default port needs it exported for both,
or the page loads and every `/api` call 404s. The perf harness additionally needs
`LM_WEB` (the Vite origin) for the client-heap measurement, which degrades to a
reported skip without it. Measured numbers live in
[`../backend/PERF.md`](../backend/PERF.md).

`npm run typecheck` passes in a clean checkout that has **never** run
`mise run wasm`: the Wasm package is declared ambiently in `core-wasm.d.ts` and
resolved at runtime through a Vite alias. Keep it that way — a typecheck that
needs a Rust toolchain is a typecheck nobody runs.
